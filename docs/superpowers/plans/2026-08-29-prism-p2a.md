# Prism Engine P2A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deterministic native Rust mirror of Civic Foundry `WorldFoundationSnapshot` and `CadastralSnapshot`, prove cross-language query/validation/mutation parity, and keep TypeScript plus Save V9 fully authoritative throughout P2A.

**Architecture:** Add a transitional `prism-domain` workspace crate beside `prism-core`. TypeScript emits a versioned JSON bridge envelope containing only existing authoritative world/cadastre snapshots; Rust decodes, validates, canonicalizes, indexes, hashes, and mutates isolated candidate copies. Cross-language fixtures and a small native parity CLI prove deterministic equality without allowing native state to commit into the live game.

**Tech Stack:** Rust 1.98.0 / Rust 2024; `serde` + `serde_json` only as new Rust dependencies; Node 22 with TypeScript type stripping; existing TypeScript `WorldFoundation`, `CadastralGraph`, `CadastralMutationSystem`, Save V9, and `clipper2-ts` as parity oracles; GitHub Actions Linux + Windows gates.

**Spec:** `docs/superpowers/specs/2026-08-29-prism-p2a-design.md`

## Global Constraints

- Begin from branch `feature/prism-p2a`, which was created from verified P1 head `e5a5c0e961d2654dbe023f1ae5a4c3b73baa0161`.
- Rust toolchain remains exactly 1.98.0 / Rust 2024.
- `engine/prism/Cargo.lock` remains committed and every native verification command uses `--locked`.
- `#![forbid(unsafe_code)]` remains mandatory in Prism-owned Rust crates.
- P2A may add only `serde` with derive support and `serde_json` as new Rust dependencies. Do not add a Rust geometry, spatial-index, hashing, RNG, FFI, or collection crate.
- `prism-core` must remain free of Civic Foundry domain semantics; `prism-domain` may depend on `prism-core`, but `prism-core` may not depend on `prism-domain`.
- TypeScript `WorldFoundation`, `CadastralGraph`, `CadastralMutationSystem`, `CadastralRuntimeMutationService`, and Save V9 remain authoritative.
- No P2A API may mutate `SimulationCore` or write native state back into the running game.
- Save V9 remains `saveVersion: 9`, `gameVersion: '0.9.0-urban-fabric'`. No Save V10 or native persistence is introduced.
- Imported hydrology/flood state is mirror data only. Do not port or transfer `HydrologyModel`, `FloodModel`, depression resolution, or design-storm authority.
- Stable persisted/domain string IDs remain the P2A identity contract; do not replace parcel/geography IDs with ECS GUIDs.
- Canonical state must not depend on JSON object-key order, source collection iteration order, hash-map iteration order, worker completion order, profiler timing, or diagnostic metadata.
- Every task is RED/GREEN where practical and ends in a focused commit.
- Do not begin P2B authority-transfer work in this plan.

1. the internal Rust polygon kernel cannot reproduce the committed TypeScript geometry oracle for the approved fixture surface;
2. world/cadastre parity would require changing Save V9 semantics;
3. a proposed fix requires making native P2A a live gameplay mutation source;
4. a parity mismatch appears to be an intentional semantic improvement rather than a port of current behavior;
5. a required Rust dependency exceeds the approved `serde`/`serde_json` allowance;

Those conditions are P2A architecture questions, not implementation bugs to hide.
