# Prism Engine P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Prism's complete P1 native archetype ECS and deterministic parallel job execution fabric without transferring Civic Foundry gameplay authority.

**Architecture:** P1 extends the P0 Rust core with safe 64-byte-aligned byte-oriented SoA archetype chunks, deterministic structural command buffers, compiled execution waves, a persistent standard-library worker pool with deterministic admission/work stealing, an executor that commits results in stable order, execution epochs, strict ECS hashing, and non-authoritative profiling. All structural ECS mutation occurs after execution barriers, so entity recycling is epoch-safe by construction.

**Tech Stack:** Rust 1.98.0 / Rust 2024, standard library only, existing `engine/prism` Cargo workspace, GitHub Actions, Node 22 repository verification.

**Spec:** `docs/superpowers/specs/2026-08-29-prism-p1-design.md`

## Global Constraints

- Rust toolchain remains exactly 1.98.0 / Rust 2024.
- `engine/prism/Cargo.lock` remains committed and verification uses `--locked`.
- No third-party Rust dependencies in P1.
- Preserve `#![forbid(unsafe_code)]`.
- No Save V10, Chrono-Lattice, D3D12, native world/cadastre import, continuum solvers, ML, rendering authority, or gameplay-authority migration.
- P0 Windows bootstrap output must remain exactly `PRISM_BOOTSTRAP version=0.1.0 entity_generation=1 alignment=64 compiled_jobs=2`.
- Every production behavior is introduced through RED → GREEN tests.

### Type consistency

`JobId` is the stable issuer identity across graph compilation, structural command keys, executable job lookup, worker task results, and profiling. Structural command buffers remain ECS-owned and executor outputs carry them without applying them. `EcsWorld` remains the sole owner of archetype structural state.

### Placeholder scan

The plan intentionally contains no deferred P1 behavior. P2 and later systems are explicit out-of-scope boundaries rather than placeholders.
